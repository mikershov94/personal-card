# Стиль кода и автоматические проверки

## TypeScript

- Новый код пишется на TypeScript.
- Включены `noImplicitAny` и `strictNullChecks`.
- Объектные структуры и предметные сущности описываются через `interface`. Алиасы `type`
  используются только для преобразований через utility types и конструкций, которые нельзя
  выразить интерфейсом, например union или mapped types.
- Frontend read models описываются как полностью `readonly`; новые состояния создаются без мутации
  исходных объектов и коллекций.
- Публичные методы классов объявляются с `public` и явным возвращаемым типом.
- Внедрённые зависимости объявляются как `private readonly`.
- `any` запрещён в production-коде. В тестах его использование также следует избегать.
- Обещания не оставляются без обработки.
- Небезопасные присваивания и аргументы исправляются типизацией, а не отключением правил.
- Имена методов должны совпадать по смыслу между resolver, service и repository.

## Импорты

- Относительные пути записываются в минимальной нормализованной форме: `../module`, а не
  `./../module`.
- Правила границ и публичных API frontend slice описаны в `public-frontend.md`.

## Именование файлов

- `*.input.dto.ts` — входной GraphQL DTO.
- `*.entity.ts` — GraphQL output-тип.
- `*.repository.ts` — класс доступа к данным.
- `*.spec.ts` — unit-тест.
- `*.e2e-spec.ts` — e2e-тест.

## Форматирование

Корневой `.prettierrc` является единым конфигом форматирования монорепозитория:

- 4 пробела для отступа;
- пробелы вместо табов;
- одинарные кавычки;
- обязательные точки с запятой;
- trailing comma в поддерживаемых конструкциях;
- ширина строки — 100 символов.

Prettier является единственным formatter для TypeScript и JavaScript. Prisma-файлы
форматируются Prisma formatter.

## ESLint

- Используется единый корневой flat config `eslint.config.mjs`.
- ESLint выполняет type-aware проверки TypeScript.
- Импорты и экспорты сортируются через `simple-import-sort`.
- Неиспользуемые значения удаляются или намеренно именуются с `_` согласно конфигу.
- Отключение lint-правила допускается только локально и с понятной причиной.
- Не следует ослаблять общее правило ради исправления одного файла.

## VS Code

- Форматирование выполняется при сохранении через Prettier.
- Автоопределение отступов отключено; используется 4 пробела.
- ESLint показывает диагностику, но не выступает formatter.
- `source.fixAll.eslint` не запускается автоматически при сохранении.
- Массовые ESLint-исправления выполняются явной командой и проверяются через diff.

## Команды

Из корня репозитория:

```shell
pnpm format
pnpm format:check
pnpm lint
pnpm lint:fix
pnpm typecheck
```
