# Реализация backend-фич

## Последовательность

Типовая предметная фича реализуется следующими блоками:

1. Сформулировать бизнес-сценарии и внешний GraphQL-контракт.
2. Описать Prisma-модель и необходимые ограничения данных.
3. Создать и проверить миграцию, затем сгенерировать Prisma Client.
4. Описать GraphQL entity.
5. Описать input DTO и правила `class-validator`.
6. Написать unit-тесты repository и реализовать Prisma-запросы.
7. Написать unit-тесты service и реализовать сценарии использования.
8. Написать unit-тесты resolver и реализовать GraphQL query/mutation.
9. Зарегистрировать зависимости в NestJS-модуле.
10. Добавить e2e happy и negative сценарии.
11. Выполнить полный набор локальных проверок.
12. После merge проверить миграции, health endpoints и публичный GraphQL-контракт.

Если контракт слоя уже определён, тесты пишутся до его реализации. Порядок можно изменить,
если это обосновано зависимостями задачи, но нельзя пропускать проверки соответствующего слоя.

## GraphQL-контракт

- Resolver не содержит бизнес-логику.
- Аргумент mutation обычно называется `input` и имеет отдельный `@InputType`.
- Частичное обновление использует отдельный DTO с nullable GraphQL-полями и
  `@IsOptional()` для валидации.
- Возвращаемая entity не должна раскрывать внутренние или секретные поля базы данных.
- Удаление возвращает понятный GraphQL-результат, например `Boolean`.

## Работа с данными

- Repository принимает собственный тип данных или DTO только когда их контракт действительно
  совпадает.
- Prisma-запросы не выходят за пределы repository и инфраструктурных сервисов.
- Бизнес-константы вроде идентификатора singleton-профиля именуются и хранятся централизованно.
- Singleton обеспечивается ограничением модели и явным условием поиска, а не предположением о
  количестве строк.
- Ошибка отсутствующей записи должна иметь предсказуемое отображение в GraphQL-ответе.

## Definition of Done

Фича готова к PR, когда:

- внешний контракт реализован и проверен;
- миграции воспроизводимы на чистой БД;
- unit happy и negative сценарии проходят;
- e2e happy и negative сценарии проходят;
- форматирование, lint, typecheck и build проходят;
- в репозитории нет секретов и случайных локальных файлов;
- документация для ИИ-агентов обновлена, если появилось устойчивое соглашение или новый
  существенный codepath.
